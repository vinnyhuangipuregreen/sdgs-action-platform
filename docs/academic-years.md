# 學年度資料隔離改版：盤點與實作規格

狀態：主平台、配對挑戰賽及課程登錄已發布；正式站年度清單及新版本已確認。管理員原憑證回傳 401，登入後正式資料比對待重新登入完成。

## 固定需求

- 現有平台資料歸入編號 1、2026 學年度、期間 202609–202706。
- 學員在登入前選擇學年度；登入後各模組只能讀寫選定學年度的資料。
- 全站 Header 顯示學年度與期間，跨站登入後保持一致。
- 管理後台可切換學年度，提供新增、修改、刪除、查詢。
- 新編號為目前最大編號加一，資料庫需防止同時新增造成重複。
- 學年度可選 2026–2050，期間開始與結束月份分別選擇，結束不可早於開始。
- 刪除前檢查全部模組，僅列出筆數大於零的關聯；無法取得任一模組計數時不可放行刪除。

## 已確認的資料政策

1. 新年度複製選定來源年度的教材、分類、示範與遊戲設定；練習單、遊戲成績、課程、出席與報名名冊從空白開始。
2. 學員共用身份帳號，各年度獨立報名名冊。姓名、電話、補課信箱與分會資料以年度名冊為準；帳號信箱及自訂密碼共用。移除年度報名不刪除共用帳號。

注意：若複製 SDGs 17 目標／169 細項即算有關聯資料，依目前指定的刪除規則，該年度建立教材後就不能直接刪除。

## 實作順序與驗證

1. 依上述資料政策建立學年度主檔、輸入驗證與遷移測試。
2. 擴充登入憑證、SSO 與後台切換；過期／不存在／無報名資格的年度不可存取。
3. 主平台、配對挑戰賽、課程登錄分別落實資料隔離，包含直接以其他年度資料 ID 呼叫 API 的拒絕測試。
4. 建立年度管理 UI、Header 年度資訊、登入下拉選單；切換時清除前一年度的編修狀態與快取。
5. 驗證兩個年度相同學員、不同資料：列表、圖表、成績、教材、課程、出席與所有匯出均不混用。
6. 驗證刪除：無關聯年度可刪，有任一關聯則拒絕並列出實際筆數；上游服務失敗時拒絕刪除。
7. 核對 2026 資料保留原表、原 ID 與原課程資料包，正式發布後比對關聯統計與匯出，再驗證跨專案部署。

## 必要的失敗案例

- 學員不能透過更改查詢參數取得其他年度資料。
- 已開啟的歷史編輯視窗、遊戲場次與下載連結不能在切換年度後混用。
- 相同瀏覽器不同分頁切換年度，不得把舊分頁的表單寫進新年度。
- 年度刪除檢查與寫入同時發生時，不可產生失去年度歸屬的紀錄。
- 後台代理、CSV／Word／XLSX 與 SSO 不能遺失年度限制。
- 遷移可重複執行，不能重複複製或覆蓋既有 2026 資料。

## 儲存及授權方式

- 原 2026 年度使用原表及原課程 payload，不搬移、不重編 ID。
- 主平台與配對賽使用同一資料庫內的年度表命名空間，例如 `ay2_worksheets`；只轉換明確列入清單的資料表名稱，身份與 SSO 表共用。表、索引及分類連動觸發器一併建立。
- 課程使用 `annual_attendance_state`，各年度獨立 payload 與樂觀鎖版本；原 `attendance_state` 保留為 ID 1。
- 登入憑證與 SSO 票券包含年度。後端以驗證後憑證決定年度；不接受與憑證不一致的年度參數。公開教材與訪客遊戲沿用原存取規則，網址指定年度。
- 新年度先處於 initializing 狀態，三個模組全數初始化成功才開放登入。失敗可用同一 ID 重試，不清除已建立資料。
- 刪除需確認各模組關聯筆數為零；任一模組無法查詢則拒絕。刪除保留編號墓碑，避免重新使用舊 ID。

## 本機驗證

- 主平台 Python、JavaScript 回歸測試；配對賽及課程 Python 回歸測試；課程表單 JavaScript 回歸測試。
- 三個實際服務以獨立 SQLite 測試庫互連：新增 2027、複製教材、空白紀錄與名冊、同帳號加入年度名冊、學員選年度登入。
- 課程 UI 在 2027 新增一堂課後，切回 2026 仍為原本兩堂課；原簽到紀錄保留。
- 年度頁首與練習單於 1920、1440、1366、1280、1024、768、390px 量測皆無整頁水平溢出。
- 測試資料僅建立於本機測試庫，正式站不建立測試學年度。
